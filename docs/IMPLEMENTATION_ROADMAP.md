# GovCode Harness 이후 구현 계획

> 제품 전체 목표는 [제품 방향](PRODUCT_DIRECTION.md)을 따른다. 아래 R1~R6와 기존 MVP는 첫 Vertical Slice 및 공통 기반의 계획이다. 다른 규정 분야는 적용 요구·규정 팩·수행 작업·산출물·충족 현황·변경 영향을 후속 설계한다.

기준일: 2026-10-30 KST / 현재 코드: v0.10.0 / 상태: R7-A~D·문서 초안 로컬 참조 구현·외부 운영 조건 대기

R1-C~R6의 소프트웨어는 로컬 참조 범위로 구현·검증했다. [랄프 완료 보고](RALPH_COMPLETION_REPORT.md)에 현재 결과와 외부 미완료 조건을 구분했다.
아래 단계별 내용은 최초 계획과 실제 운영 적용 시의 종료 기준을 함께 보존한다. 실제 기관 승인·배포·실데이터 파일럿 완료로 읽지 않는다.
먼저 입력 스냅샷과 CI 판정을 안정화하고, 탐지 범위와 정책 승인, 증적 보관을 단계적으로 붙인다.
중앙 관리와 AI 수정 지원은 이 기반을 갖춘 뒤 진행한다.
이 문서는 이후 구현 순서와 단계별 완료 기준의 기준 문서다. [기존 MVP 백로그](MVP_BACKLOG.md)의 작업 ID는 유지한다.
아래 버전명은 계획용이며 출시일이나 구현 완료를 뜻하지 않는다.

## 2. 공통 구현 원칙

- 기관 내부 실행과 결정적 정책 판정을 유지한다. AI는 설명과 수정안만 제안한다.
- 오류·누락·미분석·만료·증적 실패를 allow로 바꾸지 않는다.
- 법령 원문의 의무, 기관 규정, 예시 정책, 미확인 요구를 계속 구분한다.
- 민원 원문·원본 로그·비밀값을 프롬프트·표준 출력·증적에 복사하지 않는다.
- 검사 대상 코드와 그 저장소의 설정·스크립트를 신뢰하지 않는다.
- 단계마다 새 시험과 실제 전후 실행, 독립 검토를 완료한다. 정책·도구·스키마 변경도 같은 절차를 따른다.
- 기존 회귀를 유지한다. 동작 계약을 변경할 때는 이유·버전·이전 결과와의 차이를 기록하고 시험을 갱신한다.
- 원격 게시·배포·실데이터 처리는 검토 가능한 구현과 결과를 먼저 준비한 뒤 해당 작업의 승인을 받는다.

## 4. R1 실제 저장소 입력과 CI 판정 준비

### 구현 범위

1. 스냅샷 수집을 실행·판정 코드와 분리한다. 입력 commit, 전체 파일 목록, 검사·미검사 사유와 digest를 고정한다.
2. 명시적 commit 스냅샷 모드를 추가한다. 작업 폴더 전체 검사와 커밋 검사 결과를 구분해 출력한다.
   커밋 모드에서 미커밋 파일을 검사했다고 표시하지 않는다. 기존 엄격 모드는 유지한다.
3. 캐시·가상환경·CI 산출물이 있는 저장소에서도 요청한 commit을 읽을 수 있게 한다.
   검사 범위 밖 파일과 미지원 코드 파일을 구분하며, 제외를 근거 없이 안전으로 집계하지 않는다.
4. 파일 수·용량·시간 상한을 검토 가능한 실행 설정으로 관리한다. 상한 초과는 오류 또는 불완전 상태다.
5. CI가 전달한 예상 commit과 실행 결과·현재 변경을 대조하는 게이트를 추가한다.
6. CI에 필요한 JSON 요약, 종료 코드, 정제 증적 산출물 계약과 제공자 중립 실행 예제를 만든다.

### 완료 기준

- 요청한 commit과 다른 결과, 실행 중 변경된 head, 누락 검사·증적을 게이트가 거부한다.
- 같은 commit·정책·도구에서 정규화한 판정과 Finding 집합이 재현된다.
- 심볼릭 링크·경로 탈출·외부 통신·저장소 확장 프로그램 실행에 대한 부정 시험을 통과한다.
- dirty tree를 허용한 명시적 커밋 모드는 실제 검사 범위를 정확히 보고한다.
- 위험본 거부와 수정본 통과를 CI 계약 시험에서 확인한다.
- 원격 CI 미선정 상태에서는 로컬 CI 시뮬레이션까지만 완료로 표시한다.
  실제 필수 체크·보호 브랜치는 원격 저장소와 CI를 정한 뒤 별도로 검증한다.

## 5. R2 탐지 범위와 독립 평가

### 구현 범위

- 현재 corpus와 별도로, 실제 API 코드 형태를 본뜬 합성 양성 50개·음성 50개를 초기 목표로 만든다.
  이 수치는 제품 평가 목표이며 법정 기준이 아니다.
- 정답 근거와 source·sink·수정 후 기대 동작을 검토한다. 개발용과 최종 평가용 표본을 분리한다.
- 요청 데이터 source, 로그 sink, 검토된 정제 함수와 로그 래퍼를 명시적으로 모델링한다.
- 같은 파일의 도우미 함수·분기·예외·별칭을 순서대로 지원한다. 기능마다 지원·부분 분석·미지원 상태를 기록한다.
- request_id 같은 이름에 대한 기존 신뢰 가정을 실제 호출 계약·생성 경로와 구분한다.
  기관 적용 모드에서 출처를 확인하지 못하면 이름만 보고 안전으로 확정하지 않는다.
- 실제 개발 언어가 정해지면 해당 언어 어댑터를 별도 PoC로 평가한다. 지금은 Python 흐름을 우선한다.

### 완료 기준

- 전체 표본 수, 지원 비율, 정밀도·재현율, 오류·검토 필요 비율을 함께 보고한다.
- 분석하지 못한 사례를 조용히 제외해 정확도를 높이지 않는다.
- 지원 범위의 초기 목표는 탐지 재현율 95% 이상·음성 오탐 5% 이하로 둔다.
  고위험 정답 사례가 allow로 빠지면 확대 적용을 중단한다.
- 새 지원 구문에서 원래 차단 사례가 통과하지 않는 회귀 시험을 추가한다.
- 수정 예제는 응답·업무 동작과 필요한 감사 이벤트를 유지한다.
- 수치가 미달하면 원인을 기록하고 지원 범위를 줄이거나 개선한다. 통과 기준을 낮춰 결과를 맞추지 않는다.

오철칙은 동일 표본과 고정 프로필에서 추가 탐지·오탐·미분석·실행 비용을 다시 평가한다.
추가 가치가 확인될 때까지 기본 활성화하지 않는다.

## 6. R3 규정 적용성과 정책 수명주기

### 구현 범위

1. 공식 출처의 원문 버전·기준시점·조항 시행 구간·부칙·기관 적용성 판단을 저장한다.
2. 미확정인 REG-LOG-008의 시행 유예와 기준일 적용본을 공식 원문에서 대조한다.
   이 문서는 해당 법적 내용을 새로 확정하지 않는다.
3. 기관·프로젝트 프로필과 Source→Obligation→Control→Policy 연결을 검증한다.
4. 초안→검토→승인→발행→만료·철회 상태 전이를 구현한다. 작성자와 승인자를 분리한다.
5. 승인 정책 묶음의 버전·범위·서명·만료·역행을 검사하고, 오프라인 캐시 유효기간을 관리한다.
6. 예외는 최소 범위·보완통제·독립 승인·만료를 요구한다. 법적 의무 자체의 면제로 처리하지 않는다.

### 완료 기준

- 조문 확인, 기관 적용 판단, 정책 승인을 서로 대체하지 않는다.
- 미확정 적용성·시행 구간, 승인되지 않은 정책, 서명 오류·만료·범위 불일치·철회 정책이 게이트를 열지 못한다.
- 자기 승인·다른 기관 예외·만료 예외·범위 밖 예외를 거부한다.
- 중앙 장애나 오프라인 상태에서도 정한 유효기간 안의 승인본만 사용한다.
  철회 정보의 전파 지연과 대응 절차를 문서화한다.
- 운영 서명키·승인 권한이 미정이면 개발키와 합성 역할 시험으로 제한하고 운영 승인 완료로 표시하지 않는다.

법령 MCP, 규정 MCP Builder, Kordoc은 자료 입력·구조화 후보로만 둔다.
조회·추출 결과가 법적 판단이나 자동 정책 승인이 되지 않도록 한다.
기관 규정은 승인된 자료만 사용하고, 외부 AI·공개 배포 경로는 별도 허용 전 사용하지 않는다.
한국어 PDF는 렌더링·OCR와 원문 대조를 기본으로 하고, 추출 오류가 있으면 사람 검토로 남긴다.

## 7. R4 증적의 이동성과 보관

### 구현 범위

- 절대 폴더 위치 대신 Run ID·상대 아티팩트·내용 digest로 연결하는 내보내기 묶음을 설계한다.
- 여러 수정·검토 실행의 부모 관계를 보존하고 누락·순환·다른 기관 참조를 검사한다.
- 정규화·스키마·서명 형식을 버전 관리하고, 서명키 교체·접근 권한·보관·복구를 연결한다.
- 과거 기록의 무결성 확인과 현재 변경의 병합 가능 판정을 별도 결과 유형으로 분리한다.
- 과거 기록 확인에는 현재 도구를 다시 실행할 수 없는 사유를 표시한다.
  이 결과를 현재 commit의 allow로 변환하지 않는다.
- 이전 도구의 실제 재현 실행은 승인된 아티팩트와 제한 환경에서 별도로 수행한다.
- 기관 보존 분류·접근·파기·보존 중지 절차를 결정하고 저장소 어댑터에 반영한다.

### 완료 기준

- 폴더를 옮겨도 같은 기록 묶음의 무결성을 확인할 수 있다.
- 누락·변조·유효하지 않은 서명·부모 순환·다른 기관 참조를 거부한다.
- 과거 무결성 확인 결과나 오래된 판정으로 현재 CI 게이트를 열 수 없다.
- 원문 민원·원본 로그·비밀값을 제외하고, 원본 코드는 기관 저장소 참조와 digest로 연결한다.
- 실제 복구 시험과 권한별 읽기·삭제 시험을 수행한다.
- 증적 보유기간을 법정 접속기록 기간과 혼용하지 않는다. 임의의 보관 일수를 법정 기간으로 설정하지 않는다.

## 8. R5 중앙 관리와 파일럿

### 구현 범위

- 최소 관리 화면에서 실행 현황·검토 대상·규정 적용성·정책 승인·예외·증적 연결을 보여 준다.
- 기관·프로젝트·역할별 조회·변경 권한과 접근 감사를 적용한다.
- 중앙은 허용한 요약과 정책 묶음만 다룬다. 기관 내부 완전 설치도 가능한 경계를 유지한다.
- 기관과 저장소를 선정한 뒤 한정 파일럿을 진행한다.

### 완료 기준

- 다른 기관·프로젝트의 실행·정책·증적을 읽거나 참조할 수 없다.
- 정책 작성·승인·운영 권한 분리를 실제 역할로 확인한다.
- 담당자가 지적을 재현하고, 수정·재검사·검토·예외 이력을 추적할 수 있다.
- 파일럿 기간·표본·성공 기준을 착수 전에 합의한다.
  탐지·오탐·검토 부담·검사 지연·재작업을 함께 측정한다.
- 기관 적용성 검토·보안 검토·보관 정책·운영 책임자를 확정하기 전에는 기관 배포 완료로 표시하지 않는다.

## 9. R6 제한된 AI 수정 지원

### 구현 범위

- 허용한 최소 자료만 모델 게이트웨이에 전달한다. 기본 외부 전송은 비활성으로 둔다.
- AI는 설명과 변경 제안만 생성한다. 정책·예외 승인과 gate 판정 권한은 주지 않는다.
- 적용 전 변경 범위를 보여 주고, 승인된 수정은 새 commit에서 전체 필수 검사를 다시 수행한다.
- 기능·감사 이벤트 회귀, 시험 삭제·skip 추가·억제 주석·기준 완화 등 우회 변경도 확인한다.

### 완료 기준

- 프롬프트 주입·과도한 파일 변경·원문 반출 시도를 차단한다.
- AI 중단·시간 초과 때 수동 수정·재검사 경로로 계속 진행할 수 있다.
- AI가 생성에 성공했다는 이유로 통과시키지 않는다.
- 기존 합성 고정 수정과 일반 코드 제안·적용을 구분해 보고한다.
- 모델·프롬프트·도구 버전, 사람이 승인한 diff와 재검사 결과를 연결한다.

## 11. 일정과 다음 착수 단위

현재는 우선순위와 종료 조건을 정한 계획이며 확정 일정·공수 약속은 아니다.
R1-A의 입력 계약과 대상 저장소 조건을 확인한 뒤 티켓별 공수·담당자·착수일을 산정한다.
기관 검토·원격 권한·운영 인프라 대기와 구현 시간을 따로 기록한다.

**R1-A와 R1-B는 구현했다.** 독립 스냅샷 계약과 --commit 모드, 기본 검사 호환·범위 시험을 추가했다.
[실행 범위와 사용법](SNAPSHOT_COMMIT_MODE.md)을 따른다. R1-C의 예상 commit 게이트와 R1-D 실행 예제, 이후 참조 기능까지 구현했다. 다음 실제 적용은 대상 저장소·CI·기관 운영 조건을 확정한 뒤 진행한다.
R1-E에서 전체 회귀·실제 전후 실행·독립 검토를 마친 뒤 원격 연결 여부를 결정한다.

완료 보고에는 구현한 범위, 수행한 검사, 남은 결정과 제약을 적는다.
다음 단계는 앞 단계의 완료 기준을 충족한 뒤 진행하며, 알려진 실패를 통과로 보고하지 않는다.

서명된 규정 팩의 작성·제출·독립 승인·발행·잠금과 3값 적용성 판단을 구현했다. [실행 안내](RULE_PACK_APPLICABILITY_RUNBOOK.md)를 따른다.

다음 단위는 R7-E 산출물·추적 검사다. 요구 충족·새 단계 게이트·화면·통합 인수는 아직 완료하지 않았다.
