## 마일스톤

- M0: 규정 적용 검토와 계약 확정(GCH-001~002). 기관 답변이 늦으면 합성 데이터로만 후속 개발한다.
- M1: 로컬 Vertical Slice(GCH-003~007). 위험 finding→deny→수정→새 실행→증적을 한 흐름으로 입증한다.
- M2: 실제 병합 통제와 운영 준비(GCH-008~010,013). 보호된 브랜치·정책 승인·증적 저장을 연결한다.
- M3: 선택적 중앙 관리·AI(GCH-011~012). 기관 반출 승인이 없으면 내부 설치·로컬 모드로 완료한다.

## Vertical Slice 완료 정의

`tests/ACCEPTANCE.md`의 필수 시나리오가 모두 실행되어야 한다.
위험 변경은 CI에서 거부되고, 수정은 별도 commit으로 재검사해야 한다.
API 응답 동작과 필요한 감사 기록은 유지돼야 한다.
증적은 수정 전후 판정과 정책·도구·검사 범위를 재현할 수 있어야 한다.
변조·증적 누락·오래된 결과·기관 간 참조·만료 예외는 통과하지 않아야 한다.
미지원 언어의 clean 결과를 allow로 보고하지 않아야 한다.

## 검증 전략

단위 시험은 정책 우선순위·만료·범위·참조 오류를 검증한다.
통합 시험은 소스→finding→decision→evidence 연결을 검증한다.
회귀 시험은 민원 응답, 일반 로그, 필수 감사 이벤트를 분리해 검사한다.
CI 시험은 실제 보호 규칙과 실행 중 head 변경을 포함한다.
보안 시험은 비신뢰 코드 실행 격리, 프롬프트 주입, 외부 전송, 기관 간 접근을 포함한다.
AI 출력은 생성 성공률보다 적용 후 필수 검사를 통과했는지 평가한다.

## v0.4.0 R1-A R1-B

독립 스냅샷 수집, 파일별 분류·이유·digest, 명시적 전체 commit SHA 검사를 구현했다.
기본 엄격 HEAD 검사는 유지하며 명시 모드는 작업 폴더를 검사하지 않았음을 결과·증적에 기록한다.
과거 commit 증적은 같은 SHA를 명시해야 검증한다. 현재 PR·CI의 예상 commit 대조와 원격 필수 검사는 R1-C·R1-D에 남아 있다.
[계약과 실행 안내](SNAPSHOT_COMMIT_MODE.md)를 따른다. GCH-008 전체를 완료한 것으로 표시하지 않는다.

## v0.9 로컬 참조 완료

R1-C~R6의 소프트웨어를 연결했다. 기존175개를 포함해 최종320개 회귀를 통과하고 서명·권한·예외·증적 일관성 검토의 발견 사항을 수정했다.
