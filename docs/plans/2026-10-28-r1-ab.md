# R1-A와 R1-B 구현 계약


기준일: 2026-10-28 KST / 사용자 승인 범위: 스냅샷 수집 분리·명시적 commit 모드·기존 회귀 확인
목표 코드 버전: v0.4.0. R1-C의 CI 게이트와 R1-D의 원격 CI 설정은 이번 범위가 아니다.

## 입력 계약

기존 기본 모드는 strict_head다. 현재 HEAD를 고정하고 작업 파일·index·비추적 파일을 엄격하게 확인한다.
scan --commit에는 소문자 40자리 commit SHA만 받는다. branch 이름·HEAD·짧은 ID·tag 객체·blob은 받지 않는다.
명시 모드는 commit_snapshot이며 선택한 commit의 Git 원본만 읽는다. 미커밋·staged·미추적·ignore 파일은 검사하지 않는다.
그 사실을 input_mode, scope, worktree_checked와 commit_sha에 기록하고 현재 HEAD와의 일치 여부를 요약한다.

## 스냅샷 모듈

snapshot.py가 Git 읽기·commit 검증·파일 분류·상한·원문 없는 manifest를 담당한다.
collect의 sources는 내부 분석 입력이다. 영구 기록은 manifest 허용 필드만 사용한다.
원문 없이 경로·내용 digest·크기·분류·미분석 사유·전체 크기를 snapshot.json에 기록한다.
모든 새 실행에서 이 아티팩트를 봉인·재검증한다. 단순 문서·설정 파일의 분류를 코드 검사 통과로 표시하지 않는다.
기존 snapshot tuple 호출은 호환 shim으로 유지해 기존 회귀를 보존한다.

## 검증 계약

기본 verify는 증적 commit과 현재 HEAD를 대조한다. strict_head는 작업 트리도 엄격하게 확인한다.
commit_snapshot의 작업 폴더는 검증하지 않으며 그 사실을 표시한다.
과거 commit을 검증하려면 verify --commit에 증적과 같은 SHA를 명시해야 한다.
이 옵션은 commit_snapshot 증적에만 적용한다. strict_head 증적의 dirty 검사 우회로 사용하지 않는다.
명시한 commit 검사·재검증의 allow는 선택한 commit의 결과이며 현재 PR이나 작업 폴더의 병합 승인으로 해석하지 않는다.
CI의 예상 commit 대조와 실제 병합 보호는 R1-C 이후에 구현한다.

## 상태 연결과 호환성

검사 모드는 execution 메타데이터와 실행 provenance에 연결한다.
모드·스냅샷 제거·변경 후 해시만 다시 계산하는 우회를 거부한다.
부모 실행은 같은 입력 모드·검사 프로필을 사용하며 원래 부모 commit을 다시 검사한다.
오철칙 선택 모드는 유지한다. 설치 환경이나 고정 프로필을 변경하지 않는다.
v0.3 증적을 v0.4의 통과 증적으로 자동 승격하지 않는다. 새 도구 지문·필수 아티팩트로 새 실행을 만든다.

## 인수 기준

- 기존 146개 회귀 시험을 유지한다.
- 실제 Git 저장소에서 commit 고정, 전체 파일 범위·이유·digest의 결정성을 확인한다.
- 지원·미지원·빈 입력·인코딩·경로·symlink·gitlink·파일 수/크기/합계 상한을 검사한다.
- Git 출력·실행 시간과 자체 프로세스 그룹을 제한하고 외부 helper·hook·filter·통신을 차단한다.
- dirty 작업 폴더의 명시적 commit 검사와 기존 기본 모드의 거부를 함께 확인한다.
- 과거 commit·잘못된 commit·부모 모드·모드 강등·스냅샷 변조·CLI 종료 코드를 검사한다.
- 원문·미검사 파일의 marker를 stdout·증적에 복사하지 않는다.
- 전체 회귀·실제 기본/명시 모드 실행·선택적 오철칙 연동·JSON 계약·독립 검토를 완료한다.
