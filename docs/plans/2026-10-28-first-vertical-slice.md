# 첫 Vertical Slice 로컬 구현 계획

상태: 로컬 구현 및 실행 검증 / 요청: 2026-10-28 / 사용자가 기존 설계를 바탕으로 실제 로컬 실행을 요청했다.

## 실행 결정

별도 승인 질문 없이 요청된 로컬 기능을 구현한다. 기존 법령 적용 범위는 변경하지 않는다.
현재 저장소에는 커밋이 없으므로 기존 스캐폴드를 유지하면서 같은 저장소에 코드를 추가한다.
원격 게시·운영 배포·프로젝트 저장소 커밋은 하지 않는다.
새 commit 연결을 검증하기 위해 데모가 생성하는 별도 합성 Git 저장소에서만 두 개의 commit을 만든다.
분석 입력 코드는 실행하지 않는다. 수정은 데모가 생성한 정확히 알려진 합성 코드에만 적용한다.

## 구현 단위와 계약

1. Python AST 분석기: analyze(source, path) → findings, issues, parsed.
   요청 데이터가 일반 logger sink로 전달되면 finding을 만들고 미지원 구문은 검토 필요로 보고한다.
   변수명·민원값·코드 snippet·파서 오류 본문을 출력하지 않는다.
2. 로컬 실행기: Git HEAD 스냅샷 고정 → 검사 → 결정적 판정 → 원문 없는 증적과 receipt 저장·재검증.
   exit 0 allow, 2 deny, 3 review_required, 4 error. 오류·미지원·저장 실패는 통과하지 않는다.
3. CLI: demo, scan, verify, serve. 중앙 서비스·AI·정책 서명 없이 표준 라이브러리로 실행한다.
4. 합성 API: 고정된 예제의 응답·일반 로그·감사 호출을 검사하고 loopback HTTP 실행 경로를 제공한다.
5. 문서·스키마 검증 범위 갱신. 독립 검토와 실제 명령 실행으로 결과를 확인한다.

## 로컬 데모 정책

example_policy의 기관 승인 상태를 위조하지 않는다. draft/disabled 파일을 유지하고 명시적 local-demo 모드에서만 시험 규칙을 적용한다.
모든 실제 실행 증적에 이 모드를 기록한다. unsigned digest와 로컬 receipt는 변조·누락 검사 수단이며 작성자 인증·법적 증거력·운영 승인을 보장하지 않는다.
운영 모드는 제공하지 않는다. 미확정 규정은 자동 집행하지 않는다.

## 인수 기준

위험 예제 deny → 합성 수정 commit → 새 run allow → 전후 run 연결과 증적 검증.
합성 민원 원문은 stdout·증적 파일에 남지 않는다.
잘못된 구문·미지원 분석·더러운 작업 트리·오래된 head·누락/변조 증적·기존 출력 경로·심볼릭 링크를 거부한다.
정적 JSON 계약과 runtime 객체의 호환성을 확인한다.
실제 브랜치 병합 보호·운영 저장소·암호학적 서명·기관 규정 확정은 후속 작업이다.
