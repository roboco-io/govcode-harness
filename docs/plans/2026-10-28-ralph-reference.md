# Ralph 반복 실행 계획

기준일: 2026-10-28 KST / 시작 코드: v0.4.0 / 시작 회귀: 175개
요청: 남은 R1-C~R6를 구현·검증·수정 반복으로 완주한다.
완주 범위의 실제 운영/로컬 참조 구분은 사용자 확인을 기다린다. 공통 구현은 먼저 진행한다.
실제 기관 승인·배포·실데이터 파일럿은 합성 역할 시험으로 완료 처리하지 않는다.

## 실행 방식

설치된 Ralph Loop 1.0.1의 setup과 원본 stop hook을 사용한다.
플러그인의 자동 종료 훅은 Claude Code용이므로 Codex에서는 수동 체크포인트 어댑터가 원본 훅을 호출한다.
Codex 지속 실행 목표가 다음 작업을 이어 간다. 원본 프롬프트는 .runtime/ralph-full/PROMPT.md에 고정한다.
상태·반복 로그·시험 결과는 .runtime/ralph-full/에 보관한다. 다른 Claude 세션의 상태 파일은 변경하지 않는다.
성공 문구는 모든 승인 범위의 기능·인수 시험·독립 검토가 완료된 때만 출력한다.
반복 상한 40에 도달해도 미완료를 완료로 바꾸지 않는다.

## 결정과 경계

- 기존 법령 범위는 대한민국 일반 공공기관·민원 API다. 기관별 사실은 추정하지 않는다.
- 기본 검사와 종료 코드를 유지하고 오철칙은 선택 모드다.
- 실제 서명은 cryptography의 Ed25519를 사용한다. 개발 키는 새 전용 폴더에만 만든다.
- 서명·중앙 관리 참조 기능은 별도 reference 환경에서 실행한다. 기존 기본 실행은 표준 라이브러리 경로를 유지한다.
- 실제 모델이 없어도 금지·시간 초과·주입·수동 수정 경로를 시험한다. 모의 모델을 실제 모델 실행으로 표시하지 않는다.
- 실제 원격 CI·기관 권한·보존 분류·모델 반출 승인은 별도 외부 조건이다.
- 프로젝트가 아직 커밋되지 않았으므로 자동 프로젝트 commit·push·워크트리 생성은 하지 않는다.

T1·T2·T4는 독립적으로 시작한다. T3는 dev만 읽고 구현한 뒤 root가 holdout을 평가한다.
T5는 T4의 공개 서명 API를 사용하고 T6는 정책·보관 API를 연결한다.
T7은 source 실행 없이 제안을 검사하며, 실제 수정은 새 합성 sandbox에서 승인한 범위만 적용한다.
CLI 통합은 생산 모듈 인터페이스 동결 후 수행해 파일 충돌을 줄인다.

## R2 평가 조건

지원 표본을 사전에 고정하고 미분석을 점수 계산에서 숨기지 않는다.
지원 위험 탐지 재현율 95% 이상, 안전 오탐 5% 이하, 지원 표본 검토 필요 10% 이하를 목표로 한다.
모든 위험 표본에서 allow는 0건이어야 한다. 사전 미지원 표본은 review/error이며 그 비율을 별도 공개한다.
dev와 holdout을 분리해 보고한다. root 공개 평가 전에 구현 담당자는 holdout을 읽지 않는다.
이 수치는 합성 참조 평가 목표이며 실제 기관 정확도나 법정 기준이 아니다.

## 반복 체크포인트

각 반복은 바뀐 기능·새 시험·실패·수정·남은 조건을 기록한다.
원본 훅에 전달하는 JSONL은 Codex 어댑터가 작성한 프로토콜 기록이며 Claude 대화 내보내기로 가장하지 않는다.
단계별 집중 시험 후 모듈이 동결되면 전체 회귀와 실제 통합을 실행한다.
알려진 실패·미실행·외부 조건을 완료 문구로 숨기지 않는다.
