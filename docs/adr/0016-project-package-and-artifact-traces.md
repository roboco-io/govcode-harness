# ADR 0016: 프로젝트 패키지 분리와 commit 고정 산출물 검사

## 배경

프로필·규정 팩·적용성·문서 기능이 루트 실행 패키지에 늘어나고 있다. R7-E는 문서 입력과 추적 검사를 추가해야 한다.
기존 import·CLI·서명 계약을 보존하면서 책임과 입력 경계를 분리할 필요가 있다.

## 결정

프로젝트 기능은 govcode_harness/project에 모으고 이전 모듈 경로는 같은 모듈 객체를 가리키는 호환 진입점으로 유지한다.
스키마와 작성 정책 자료는 기존 설치 경로를 유지한다. 도구 digest는 하위 코드·계약·작성 정책의 변경을 반영한다.
기존 snapshot.py의 capture는 모든 정규 Git blob을 한 번 읽는다. 코드와 문서 검사는 그 캡처에 서로 다른 분류를 적용한다.
문서 검사 때문에 코드 검사의 NO_SUPPORTED_SOURCE를 제거하지 않는다.

산출물 인덱스는 기존 요구·산출물·추적 계약을 사용한다. manifest는 원문 바이트 digest와 파싱한 인덱스의 canonical digest를 함께 기록한다.
검사는 캡처 일관성, 참조·연속 경로·필수 산출물, 제한된 문서 구조와 별도의 서명 시험 실행 증명을 확인한다.
규정 팩 연결 모드에서는 원본 서명과 현재 신뢰 조건을 다시 검증하고 인덱스의 요구 전체를 대조한다.
서명 팩과 외부 도구 설정의 어댑터가 다르면 거부한다. 문서나 결과 파일의 문구를 신뢰 권한으로 사용하지 않는다.
시험 실행 증명은 commit 밖에서 서명해 자기 참조를 피한다. 결과는 구조 검사이며 요구 충족·단계 통과·독립 내용 검토를 대신하지 않는다.

## 영향과 한계

프로필·팩·적용성의 기존 호출과 원문 없는 보고를 유지한다. apps와 packages는 독립 실행 서비스가 아니라 설계·계약 경계임을 문서화한다.
문서 형식은 UTF-8 JSON과 제한된 Markdown이다. HWPX·PDF·Office·임의 문서 실행·링크 조회는 지원하지 않는다.
실제 기관 시험 어댑터·신원·보존 분류와 R7-F~I의 충족 평가·단계 게이트·증적 보관은 후속 작업이다.
[구조 안내](../REPOSITORY_STRUCTURE.md)와 [실행 안내](../ARTIFACT_TRACE_RUNBOOK.md)를 따른다.
