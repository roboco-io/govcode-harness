# ADR 0017: 현재 평가·단계 게이트·새 프로젝트 증적의 결합

## 배경

프로필과 규정 팩의 적용성만으로 프로젝트 요구가 충족됐다고 판단할 수 없다.
문서 검사 성공과 독립 검토, 기존 코드 검사, 현재 자료의 증적을 결합하되 과거 기록이 현재 통과로 재사용되지 않아야 한다.

## 결정

assessment는 원본 서명 입력과 commit을 다시 검증하고 전체 잠금 요구의 분모를 유지한다.
subject는 현재 입력과 도구에 결합하고 승인 자신을 제외한다. 최종 evaluation digest는 판정·실행 증명·검토 집합도 포함한다.
작업 안내는 요구·행동·subject로 식별한다. 미확정·미검증·검토·후속 단계·승인 제외를 충족으로 합치지 않는다.
산출물 검토는 현재 범위 author 역할과 분리한 approver가 현재 subject·요구·관련 산출물 전체에 서명한다.
문서 변경은 독립 승인한 등록 설계·추적만 새 복사본에 적용한다. 원래 commit을 실제 부모로 보존하며 원본과 Git 메타데이터를 수정하지 않는다.

stage_gate는 승인된 프로필의 코드 검사 조건을 확인하고 필요한 기존 코드 게이트를 실제 실행 검증한다.
준비 후보는 통과가 아니다. 현재 실제 저장 증적이 같은 후보에 결합할 때만 현재 단계 allow를 만든다.
새 ProjectEvidenceStore는 원본 후보를 재계산해 원문 없는 투영·서명 metadata·journal로 보관한다. 기존 archive 형식은 확장하지 않는다.
읽기는 auditor, 보존 변경·삭제·백업·복구는 operator의 대상·매개변수·시각·nonce 서명으로 검증한다.
백업과 복구는 검증한 같은 캡처 바이트와 외부 보호 checkpoint를 사용한다. 역사적 확인은 release_approval=false다.

## 사용자 흐름과 한계

화면은 서버가 선택한 현재 자료와 역할만 사용한다. 접속 토큰은 메모리에만 둔다.
만료 검토 이력은 보존하고 재검토를 허용하되 변조·미래 기록은 거부한다.
요구 8개의 합성 실행에서 현재 5개·후속 1개·승인 제외 2개를 유지한다. 전체 프로젝트 완료나 기관 승인으로 표시하지 않는다.
실모델·기관 신원·운영 키·실데이터·원격 CI·새 규정 분야는 별도 준비와 검증이 필요하다.
