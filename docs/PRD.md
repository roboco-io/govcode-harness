# GovCode Harness PRD

버전: 0.2 / 상태: 제품 목적 정리·첫 사례 구현 / 기준일: 2026-10-29 KST

> 제품 전체 목적은 [제품 방향](PRODUCT_DIRECTION.md)을 따른다. v0.9.0은 민원 API 로깅을 첫 사례로 구현했다. 아래 MVP 인수 기준과 현재 참조 구현을 모든 규정 분야의 완료 기준으로 일반화하지 않는다.

## 1. 문제와 제품 목적

공공 프로젝트 수행자는 적용되는 각종 법령·규칙·가이드라인을 파악하고, 이를 설계·개발·시험·검수·운영의 실제 작업과 산출물로 옮겨야 한다.
GovCode Harness는 적용 요구를 구조화하고, 필요한 작업을 안내하며, 자동 검사·수정 지원·담당자 검토·승인·증적을 연결해 요구 충족을 돕는다.
프로젝트 조건과 규정이 바뀌면 영향을 받는 요구와 다음 작업을 다시 확인하는 것이 목표다.

첫 Vertical Slice는 민원 API 개인정보 로깅이다. 이는 공통 흐름의 검증 사례이며 제품 전체 범위가 아니다.
현재 구현은 제한된 Python 분석과 합성 역할·자료 기반이다. 규정 전반의 자동 적용성 판단·범용 산출물 검사·충족 현황 안내는 후속 설계 범위다.

## 2. 사용자와 역할

| 역할 | 필요한 결과 | 권한 경계 |
| --- | --- | --- |
| 개발자 | 위험 위치, 이유, 수정안, 재검사 결과 | 자신의 변경 수정·재검사 요청 |
| 서비스 책임자 | 기능 회귀와 배포 가능 여부 | 코드 수정 승인, 정책 변경 권한은 별도 |
| 개인정보·보안 담당자 | 적용성 판단과 통제 근거 | 법령 적용 검토, 정책·예외 승인 |
| 플랫폼 운영자 | 실행기 상태와 정책 버전 | 시스템 운영, 단독 면제 승인 금지 |
| 감사·검토 담당자 | 변경→판정→수정→증적 추적 | 허용 범위의 읽기, 원문 접근 별도 |

정책 작성자와 승인자는 분리한다. 민원인은 제품 사용자가 아니며 민원 처리의 적법성 판단도 이 제품의 기능이 아니다.

## 3. 확정 요청과 설계 가정

확정 요청: 7종 문서, 새 저장소 초기 구조, 기존 파일 보존, 법적 의무와 예시 정책 구분,
첫 Vertical Slice의 탐지→차단→수정→증적 흐름.
제품 대상: 대한민국 공공 프로젝트 수행 과정의 적용 규정과 가이드 충족 안내.
첫 구현 범위: 일반 공공기관의 일반 민원 API 개인정보 로깅 사례.

설계 가정: 기관 내부 실행을 기본값으로 하고 중앙 관리·외부 AI 연결은 선택한다.
첫 분석 언어는 Python으로 제한해 합성 예시로 검증한다. 기관의 실제 개발 언어가 Java 등으로 정해지면
해당 언어 어댑터를 별도 추가한다. 모든 언어를 지원하는 것으로 표시하지 않는다.
민원 원문을 외부 AI에 전달할 수 있다는 가정은 두지 않는다.

## 4. MVP 범위

| ID | 기능 | 인수 기준 |
| --- | --- | --- |
| FR-01 | 불변 입력 스냅샷 | 소스 커밋·트리, 정책·통제·규정 버전, 실행기 이미지를 기록 |
| FR-02 | 개인정보 로깅 위험 탐지 | 요청 객체·본문·민감 필드가 로그 sink로 전달되는 합성 양성 사례 탐지 |
| FR-03 | 검사·차단 | 활성화된 예시 정책에서 위험 발견 시 merge gate 거부; 미지원·오류는 통과 금지 |
| FR-04 | 수정 | 허용 필드 기반 구조화 로그로 변경 제안; 개발자가 적용하고 기능 검사 |
| FR-05 | 재검사 | 새 커밋으로 전체 필수 검사 재실행; 이전 통과 결과 재사용 금지 |
| FR-06 | 증적 생성 | 이전·수정 커밋, 판정, 정책 버전, 검사 범위, 무결성 manifest 연결 |
| FR-07 | 적용성·예외 | 미확정 규정을 준수로 표시하지 않음; 유효기간과 별도 승인자 요구 |
| FR-08 | 최소 반출 | 기본 외부 전송 없음; 허용된 요약만 별도 반출 심사 |

차단 대상은 개발 변경의 병합·배포다. 운영 중인 민원 요청을 실시간 차단하는 기능은 후속 범위다.
애플리케이션 로그의 개선은 개인정보처리시스템의 필수 접속기록 수집을 없애는 변경과 구분한다.

## 5. 첫 Vertical Slice

1. 개발자가 `logger.info("complaint=%s", request_body)`와 같은 위험 코드를 포함한 변경을 제출한다.
2. 실행기가 원본을 기관 내부에서 읽고, 검사 어댑터가 `Finding`을 생성한다.
3. 정책 엔진이 활성 정책과 입력의 완전성을 검사하고 `deny`를 반환한다. CI는 실패 상태를 보고한다.
4. 개발자가 민원 본문 대신 서버 생성 요청 ID, 작업 종류, 결과 코드만 남기도록 수정한다.
5. 새 커밋에서 재검사하고 API 동작·로그 내용·필수 감사 이벤트 보존을 검증한다.
6. 증적 작성기가 두 실행을 연결한다. 보관 성공과 manifest 검증이 끝나야 수정 실행을 완료로 표시한다.

## 6. 성공 지표와 종료 기준

아래 수치는 **MVP 제품 목표**이며 법정 수치가 아니다.

- 최소 20개 합성 양성·20개 합성 음성 사례에서 정밀도·재현율을 각각 측정한다. 차단 대상 양성 사례 누락 0건을 목표로 한다.
- 지원하지 않는 언어·분석 실패·누락 파일을 모두 `error` 또는 `review_required`로 보고한다.
- 같은 소스·동일 정책·동일 도구로 판정과 Finding 집합을 재현한다. 시간·실행 ID는 달라도 된다.
- 1,000줄 합성 변경 검사 p95 60초 이내를 목표로 한다. 측정 환경을 결과와 함께 적는다.
- 외부 전송 금지 시험에서 민원 본문, 비밀값, 원본 코드가 반출되지 않는다.
- 증적 변조·누락, 오래된 commit의 결과, 만료된 예외를 merge gate가 거부한다.

위 항목은 최초 MVP 목표다. 현재 합성 탐지 평가·회귀 결과는 [완료 보고](RALPH_COMPLETION_REPORT.md)를 따른다. 실제 기관 성능과 전체 규정 분야의 충족률은 측정하지 않았다.

## 7. 비기능 요구

기관·프로젝트 격리, 최소 권한, 정책 변경 감사, 승인된 아티팩트 검증, 실행 자원 제한을 적용한다.
실행기는 네트워크와 호스트 자격증명 없이 소스를 검사하며, 테스트 실행은 별도의 제한 환경에서 한다.
중앙 장애 시 승인된 로컬 정책으로 검사한다. 정책 유효기간이 지나면 차단 상태로 전환한다.
증적 기록 장애는 통과가 아니며 중복 실행은 입력 식별자로 연결한다.

## 8. 제외 범위와 다음 결정

전 법령 자동 해석, 법적 준수 인증, 운영 민원 자동 처분, 기관 전체 로그 수집기,
실데이터 학습, 전 언어 정밀 데이터 흐름 분석, 중앙 SaaS 실배포는 MVP에서 제외한다.
기관 지정, 실제 언어, 공공시스템 해당 여부, AI 사용 가능 환경, 문서·기록 보존 기준을 다음 검토에서 결정한다.

## v0.4.0 입력 범위 추가

R1-A·R1-B에서 전체 commit SHA 스냅샷 검사를 별도 모드로 제공한다. 기본 HEAD·clean tree 검사는 유지한다.
결과와 증적에 입력 모드·검사 commit·작업 폴더 확인 여부를 표시한다. 명시적 commit의 allow는 그 commit에만 적용된다.
과거 안전 commit을 현재 PR의 승인으로 사용하는 것을 방지하는 CI 문맥 대조는 R1-C 범위다.
새 실행의 원문 없는 snapshot.json은 수집 범위를 설명하며 실제 AST 검사 결과와 구분한다.

## v0.9 참조 상태

계획된 로컬 소프트웨어와 합성 인수 흐름은 [완료 보고](RALPH_COMPLETION_REPORT.md)를 따른다.
실제 서명·독립 역할·CI 예상 commit·정제 증적·보관·복구·관리 화면·격리 수정 검증을 연결했다.
모델은 fixture이며 실제 기관·법령 적용·원격 CI·실모델 품질·실데이터 파일럿은 외부 준비 조건이다.
초기 PRD의 기관 운영 완료 조건을 합성 참조 시험으로 대체하지 않는다.
